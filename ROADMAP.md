# План развития Textdrop

## Цель продукта

Быстро передать себе текст с одного устройства и продолжить на другом. Главный критерий: запись легко отправить, она сохраняется без потерь и появляется на остальных устройствах. Рабочая версия доступна на https://share.nikitalebe.dev; Docker, SQLite, существующий Caddy.

## Правила работы

- Развиваем личное приложение для одного владельца. Многопользовательские аккаунты, совместные пространства и публичные ссылки пока вне плана.
- Каждая законченная функция — отдельный коммит, проверки и запись результата в этом файле.
- Обновления сохраняют записи и секреты. Перед изменением схемы базы — резервная копия и проверяемый путь отката.
- Готовность кода и проверка на рабочем сервере учитываются отдельно: Docker из сессии разработки недоступен.
- Порядок ниже — предлагаемый рабочий приоритет; владелец может изменить его после использования очередного этапа. Сроки не назначаем до оценки конкретной задачи.

## 1. Надёжность — текущий этап

- [x] Ручная согласованная резервная копия SQLite без остановки приложения; проверка читаемости и восстановления на тестовой базе.
- [ ] Проверить резервную копию рабочего сервера и сохранить её вне сервера.
- [ ] Автоматическое расписание копирования, срок хранения и сигнал об ошибке. Место внешнего хранения выбрать с владельцем.
- [ ] Защита отправки от дублей при повторе запроса после потери ответа.
- [ ] Сохранение введённого текста при истечении сессии; определить срок жизни и очистку черновика на устройстве.
- [ ] Корректные сообщения о сбоях чтения базы и восстановлении связи; проверка входа после обновления.

Критерий завершения: копию можно восстановить; обрыв запроса не создаёт дубль; потеря сессии не уничтожает введённый текст.

## 2. Ежедневная работа с текстом

- [ ] Редактирование с защитой от перезаписи изменений с другого устройства.
- [ ] Корзина с восстановлением и понятным сроком окончательного удаления.
- [ ] Закрепление важных записей, удобные действия на телефоне.
- [ ] Безопасные кликабельные ссылки и разворачивание длинных записей.

Критерий: исправление и случайное удаление не требуют пересоздавать запись; работа удобна на телефоне и компьютере.

## 3. Большая лента и синхронизация

- [ ] Загрузка порциями, поиск на сервере, ограничение объёма ответа.
- [ ] Получение только изменений; оценить необходимость SSE вместо опроса.
- [ ] Экспорт и импорт записей с проверкой формата и защитой от дублей.

Критерий: на тестовой базе из 10 000 записей первая загрузка ограничена размером страницы; поиск находит старые записи без загрузки всей базы.

## 4. Обмен файлами

- [ ] Загрузка, скачивание и удаление файлов; сначала один файл на запись.
- [ ] Лимиты размера и общего хранилища, прогресс и повтор при ошибке.
- [ ] Приватная выдача файлов после входа, безопасные имена, резервное копирование файлов вместе с базой.
- [ ] Предпросмотр изображений после проверки основного сценария передачи.

Критерий: файл с телефона скачивается на компьютере без изменения содержимого; неавторизованный запрос файл не получает.

## 5. Быстрый доступ с устройств

- [ ] Установка как PWA и понятный режим отсутствия сети.
- [ ] Приём текста и файлов через системное меню «Поделиться» на поддерживаемых платформах.
- [ ] Управление сессиями устройств и их отзыв; оценка более удобного входа.

Критерий: передать содержимое можно через системное меню, а неподдерживаемый браузер сохраняет обычный веб-сценарий.

## Проверки каждого выпуска

Автотесты соответствующей логики, проверка входа и обмена на двух устройствах, мобильный и настольный интерфейс для UI-изменений. Измерять время появления записи и проверять сохранность текста при ошибках. Без аналитики содержимого личных записей.

## Журнал

- Базовая версия: вход, общая лента, поиск, копирование и удаление. Владелец подтвердил работу между устройствами.
- Этап 1, первый шаг: утилита согласованного SQLite backup, команда выгрузки из Docker и тест восстановления подготовлены. Проверка рабочей базы и внешнее хранение ещё не выполнены.
