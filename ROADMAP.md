# План развития Textdrop

## Цель продукта

Быстро передать себе текст с одного устройства и продолжить на другом. Главный критерий: запись легко отправить, она сохраняется без потерь и появляется на остальных устройствах. Рабочая версия доступна на https://share.nikitalebe.dev; Docker, SQLite, существующий Caddy.

## Правила работы

- Развиваем личное приложение для одного владельца. Многопользовательские аккаунты, совместные пространства и публичные ссылки пока вне плана.
- Каждая законченная функция — отдельный коммит, проверки и запись результата в этом файле.
- Обновления сохраняют записи и секреты. Перед изменением схемы базы — резервная копия и проверяемый путь отката.
- Готовность кода и проверка на рабочем сервере учитываются отдельно: Docker из сессии разработки недоступен.
- Порядок ниже — предлагаемый рабочий приоритет; владелец может изменить его после использования очередного этапа. Сроки не назначаем до оценки конкретной задачи.

Закрепление сообщений, экспорт и импорт истории исключены из продукта по решению владельца. История хранится в Textdrop и доступна через сервис на всех устройствах.

- [x] Подготовить GitHub Actions и проверяемое обновление с возвратом предыдущего образа.

- [x] Ручная согласованная резервная копия SQLite без остановки приложения; проверка читаемости и восстановления на тестовой базе.
- [x] Защита отправки от дублей при повторе запроса после потери ответа; идентификаторы сохраняются в базе и переживают перезапуск.
- [x] Черновик сохраняется в браузере до 7 дней, восстанавливается после перезагрузки/повторного входа; успешная отправка и явный выход очищают его.
- [x] Понятные сообщения при сбоях базы, сети и прокси; восстановление синхронизации и сохранение сессии после перезапуска проверены.

Критерий завершения: копию можно восстановить; обрыв запроса не создаёт дубль; потеря сессии не уничтожает введённый текст.

## 2. Ежедневная работа с текстом — завершено

- [x] Редактирование внутри сообщения, отметка об изменении, отмена и защита версий от перезаписи с другого устройства.
- [x] Корзина: восстановление с исходной датой, хранение 30 дней, окончательное удаление с подтверждением.
- [x] Безопасные кликабельные HTTP/HTTPS-ссылки в чате и корзине.
- [x] Сворачивание длинных записей до шести видимых строк, раскрытие и сохранение выбора при синхронизации. Поиск, копирование и редактор работают с полным текстом.

Критерий: исправление и случайное удаление не требуют пересоздавать запись; работа удобна на телефоне и компьютере.

## 3. Большая лента и синхронизация — завершено

- [x] Загрузка порциями по 50 записей, поиск по всей базе на сервере, ограничение числа записей и объёма ответа. Подгрузка сохраняет позицию чтения.
- [x] Получение только изменений по версии каждые 3 секунды, включая правки, удаления и восстановления на старых загруженных страницах. Для личного чата оставлен опрос; SSE пока не требуется.

Критерий: на тестовой базе из 10 000 записей первая загрузка ограничена размером страницы; поиск находит старые записи без загрузки всей базы.

## 4. Обмен файлами — следующий этап

- [ ] Загрузка, скачивание и удаление файлов; сначала один файл на запись.
- [ ] Лимиты размера и общего хранилища, прогресс и повтор при ошибке.
- [ ] Приватная выдача файлов после входа, безопасные имена, резервное копирование файлов вместе с базой.
- [ ] Предпросмотр изображений после проверки основного сценария передачи.

Критерий: файл с телефона скачивается на компьютере без изменения содержимого; неавторизованный запрос файл не получает.

## 5. Быстрый доступ с устройств

- [ ] Установка как PWA и понятный режим отсутствия сети.
- [ ] Приём текста и файлов через системное меню «Поделиться» на поддерживаемых платформах.
- [ ] Управление сессиями устройств и их отзыв; оценка более удобного входа.

Критерий: передать содержимое можно через системное меню, а неподдерживаемый браузер сохраняет обычный веб-сценарий.

## 6. Резервное копирование — в конце по решению владельца

Бэкап перед автодеплоем уже работает и остаётся включённым. Дополнительные работы отложены:

- [ ] Проверить восстановление копии рабочего сервера и сохранить копию вне сервера.
- [ ] Выбрать внешнее хранилище, настроить расписание, срок хранения и уведомление об ошибке.

## Проверки каждого выпуска

Автотесты соответствующей логики, проверка входа и обмена на двух устройствах, мобильный и настольный интерфейс для UI-изменений. Измерять время появления записи и проверять сохранность текста при ошибках. Без аналитики содержимого личных записей.

## Журнал

- Базовая версия: вход, общая лента, поиск, копирование и удаление. Владелец подтвердил работу между устройствами.
- Этап 1, первый шаг: утилита согласованного SQLite backup, команда выгрузки из Docker и тест восстановления подготовлены. Проверка рабочей базы и внешнее хранение ещё не выполнены.

- Автодеплой: SSH-ключ с принудительной командой и production secrets настроены; production ограничен master. Первый автоматический выпуск 43203860386 прошёл успешно: тесты, бэкап, healthy и публичный адрес проверены.

- Интерфейс чата: хронологическая история, ввод снизу, сохранение позиции чтения, светлая/тёмная темы. Проверены в Chromium на настольном и мобильном размерах с тестовыми данными.

- Мобильный интерфейс: компактная общая панель разделов/счётчика/поиска, раскрываемый поиск и доступные действия-иконки. На тестовых экранах область истории увеличена на 135 CSS-пикселей; настольная компоновка сохранена.

- Компактная панель и действия-иконки распространены на настольные экраны. Поиск раскрывается по кнопке на всех устройствах; на тестовом окне 1280×850 история получила ещё 130 CSS-пикселей.

- Длинные сообщения: превью из шести строк на телефоне и компьютере, раскрытие в чате и корзине, поиск по полному тексту. Браузерные проверки включают 100 000 символов, ссылки, редактирование, синхронизацию и обе темы.

- Большая лента: первая страница ограничена 50 сообщениями и размером ответа, серверный Unicode-поиск охватывает всю базу. Проверены 10 000 записей, подгрузка без дублей/скачков, изменения старых страниц, конфликты редактора, смена поиска и сбой/повтор.

- По решению владельца экспорт и импорт истории исключены из плана: история остаётся в сервисе. Этап 3 завершён, следующий этап — обмен файлами.
